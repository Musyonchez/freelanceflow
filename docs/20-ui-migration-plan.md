# 20 — UI Migration Plan

This is a re-skinning plan: apply the design system from [19-ui-design-system](19-ui-design-system.md) to the existing app's actual screens and files. **Every change here is visual/styling only.** No ViewModel, repository, navigation-graph, or business-logic file is touched. Screen structure, what data appears where, and navigation destinations stay exactly as they are today ([10-ui-ux-and-screens](10-ui-ux-and-screens.md)) — this plan only changes how those same screens are drawn.

Token names (`brand`, `mint`, `canvas`, `Shapes.medium`, `shadowHero`, etc.) match [19-ui-design-system](19-ui-design-system.md) exactly.

## Phase 1 — global theme

**Files:** `mobile/app/src/main/java/com/daleen/freelanceflow/ui/theme/Color.kt`, `Theme.kt`, `Type.kt`; `mobile/app/build.gradle.kts` (dependency addition only).

1. **`Color.kt`** — replace the stock `Purple80`/`PurpleGrey80`/`Pink80`/`Purple40`/`PurpleGrey40`/`Pink40` values with the full token set in [19-ui-design-system §1.2](19-ui-design-system.md#1-color-palette).
2. **`Theme.kt`** — set `dynamicColor` default to `false` (dynamic color pulls from the device wallpaper, which would override the new palette on Android 12+; the mock has one fixed brand identity, not a dynamic one). Build `LightColorScheme` from the §1.3 role mapping and `DarkColorScheme` from the §1.4 inferred mapping. Keep the `isSystemInDarkTheme()` switch as-is — only the two scheme objects change.
3. **`Type.kt`** — add the Google Fonts dependency and provider, then replace the single stub `bodyLarge` override with the full scale from [19-ui-design-system §2.2](19-ui-design-system.md#2-typography):
   - Add `implementation("androidx.compose.ui:ui-text-google-fonts:<compose-bom-aligned-version>")` to `build.gradle.kts` (the `androidx.compose.ui.text.googlefonts.GoogleFont` API ships in this artifact, not core `ui-text`).
   - Google Fonts' downloadable-font provider requires certificate fingerprints to verify the Google Play Services Fonts provider app at runtime; use the standard public certificate list shipped in the `GoogleFont.Provider` documentation (`com.google.android.gms`, cert set `providerCertificates = R.array.com_google_android_gms_fonts_certs`) — add the small `values/font_certs.xml` resource array Google documents for this (a handful of hex fingerprint strings), since it's required for the provider to resolve, not an optional extra.
   - Construct `ManropeFamily`/`DMSansFamily` as shown in doc 19 §2.2, pointing `fontProvider` at that `GoogleFont.Provider`.
   - This fetches fonts at runtime over network and caches them on-device (standard behavior for every app using Google's downloadable fonts, e.g. most OEM keyboards) — if offline-first guarantees ever need to cover first-run typography too, bundling the four Manrope weights + four DM Sans weights as raw `res/font/*.ttf` files is the fallback (same `FontFamily` construction, swap `Font(GoogleFont(...), provider, weight)` for `Font(R.font.manrope_bold, weight)`). Recommendation: start with downloadable fonts (zero asset bloat, matches how most teams consume Google Fonts in Compose); switch to bundled only if offline first-launch readability becomes a real complaint.
4. Add `Shapes` (doc 19 §4) to the `MaterialTheme(...)` call in `Theme.kt`'s `shape` parameter, and expose the extra named shape/shadow constants (`FabShape`, `TimerControlShape`, `PrimaryButtonShape`, `TimerCardShape`, `ActionSheetShape`, `shadowHero`, `shadowPanel`, `shadowFab`) as top-level `val`s alongside `Color.kt`/a new small `Elevation.kt`, since M3's `Shapes` object only has 6 slots and the mock uses more distinct corner treatments than that.

## Phase 2 — shared chrome

**File:** `mobile/app/src/main/java/com/daleen/freelanceflow/presentation/FreelanceFlowApp.kt`

- **`TopAppBar`**: style via `TopAppBarDefaults.topAppBarColors()` — container `canvas` (or `surface`, since the mock's top content sits directly on `canvas` with no distinct app-bar chrome), title text in `titleLarge`/Manrope 700, sign-out `IconButton` restyled to the §7.9 icon-button treatment (36dp, `Shapes.small`, 1dp `line` border) rather than M3's default borderless icon button.
- **`NavigationBar`**: restyle per [19 §7.6](19-ui-design-system.md#76-bottom-navigation-bar) — container color `Surface.copy(alpha = 0.95f)`, `NavigationBarItemDefaults.colors()` with selected icon/text = `brand`, unselected = `navInactive`, no indicator pill (the mock has no selected-state background, just a color change — set `indicatorColor = Color.Transparent`). A top hairline divider in `line` (M3's `NavigationBar` has no built-in top-border slot; add a 1dp `Divider`/`HorizontalDivider` immediately above it, or a `Modifier.drawBehind` top border). True backdrop blur is not natively exposed by a stock `NavigationBar` — see risk list.
- **FAB restyle**: this app places a `FloatingActionButton` per-screen (Work, Money, Clients), not centrally in `FreelanceFlowApp.kt`, so the actual edits are in each screen file (Phase 3), but the *spec* — `FabShape` (18dp), `brand` container, white content color, `shadowFab` — is called out once here since it's identical on every screen: `FloatingActionButton(containerColor = Brand, contentColor = Color.White, shape = FabShape, elevation = FloatingActionButtonDefaults.elevation(...))`, with the custom shadow applied via `Modifier.shadow(...)` if the default M3 elevation shadow looks too neutral-gray next to the mock's green-tinted one.

## Phase 3 — per-screen

### Shared patterns (apply once, reference from each screen below instead of repeating)

| App pattern | Current composable | Restyle target |
|---|---|---|
| Dashboard summary tile | `Card` (plain M3 default) | Metric-card style ([19 §7.3](19-ui-design-system.md#73-metric-card-2-column-grid)): white, 1dp `line` border, `Shapes.medium`, icon badge + label/value, no shadow |
| List row | `ListItem` | Panel row style ([19 §7.4](19-ui-design-system.md#74-panel--list-rows)): keep `ListItem` itself (don't replace the composable), but wrap rows in a `panel`-style container (`Shapes.large`, `shadowPanel`, `line` border) and add the 1dp top-divider rhythm between rows via `HorizontalDivider` instead of `ListItem`'s default no-divider look |
| Add/edit form | `ModalBottomSheet` | Action-sheet style ([19 §7.8](19-ui-design-system.md#78-bottom-sheet-action-sheet-style)): tinted scrim color, `ActionSheetShape`, drag handle restyle, title row with close `icon-button` |
| Simple single-field dialog | `AlertDialog` | Keep M3 `AlertDialog` structurally; recolor via `AlertDialogDefaults` — `containerColor = surface`, `titleContentColor`/`textContentColor = ink`, shape `Shapes.large` (20dp, close to M3 default but matches the panel radius), confirm button restyled to the primary-button look only if it's the dominant action, otherwise leave as default `TextButton` |
| Status/period chip | `FilterChip` / `AssistChip` | Tag/chip style ([19 §7.5](19-ui-design-system.md#75-status-tag--chip)) for status display (invoice status, deductible flag); keep `FilterChip`'s own selected/unselected visual language for *interactive* filters (period selector, tax period) since those are selection controls, not status badges — only recolor their selected-state container to `mint`/`brand` to match the palette |

### Auth (`presentation/screens/auth/AuthScreen.kt`)
Lowest-risk screen — a form, no lists/cards. Restyle text fields' focus color to `brand`, primary submit button to the primary-button spec (`PrimaryButtonShape`, `brand` fill), background to `canvas`. No structural change to the sign-in/sign-up toggle.

### Home (`presentation/screens/home/HomeScreen.kt`)
Current structure: greeting text, 3 `SummaryCard`s (Outstanding/Paid/Expenses, currently a single plain `Card` with title+amount), optional currency breakdown, "Export report" section with `FilterChip` period selector + "Export CSV" `Button`.

**Decision — one hero, not three equal cards.** The mock's home screen leads with one large hero card (a single standout figure) plus a *separate* 2-column metric grid underneath for secondary numbers. The app's three metrics (Outstanding/Paid/Expenses) are not naturally "one hero + two secondary" — they're three peers. Rather than force an arbitrary one into the hero slot (which would wrongly imply it's more important than the other two), apply the **metric-card treatment to all three**, laid out in the mock's 2-column grid (the third card wraps to its own row, full width or centered — acceptable, the mock's grid is visually tolerant of an odd count). This keeps the "three peer metrics" reality intact while still picking up the mock's visual rhythm: white card, `line` border, `Shapes.medium`, icon badge (pick a tint per metric — e.g. `blue` for Outstanding, `mint`/green for Paid, `peach` for Expenses, echoing the mock's own semantic-ish color choices), value in `titleLarge` Manrope. Argument against using the hero style for one of them: the hero card's whole visual point in the mock is the *single* top-of-dashboard balance figure — there's no equivalent single "the one number that matters" in this app's model, so forcing it would misrepresent the data, which the authority rule explicitly says not to do.

Currency breakdown list and "Export report" section (FilterChip period selector + Export CSV button) stay structurally identical; restyle the `FilterChip`s' selected state to `mint`/`brand` and the Export button to the primary-button spec.

### Work (`presentation/screens/work/WorkScreen.kt`)
- `RunningTimerCard` (currently a plain `Card`) → restyle to the dark timer-card spec ([19 §7.2](19-ui-design-system.md#72-dark-timer-card)): `TimerDark` background, white text, `TimerCardShape`, live dot (use `LiveDotRunning` since this card only renders while a timer is actually running — there's no "idle" state shown here, the card doesn't exist when nothing's running), elapsed time in `headlineSmall`/Manrope-tabular, the `Stop` `IconButton` restyled to the round `TimerControlShape` (38dp, `mint` fill, `brandDark` icon).
- `ProjectRow` (`ListItem`) → panel/project-row style: wrap the list in a `panel` container (`Shapes.large`, `shadowPanel`), add a `line` divider between rows, keep the existing play/stop `IconButton` trailing content but add a thin `brand`-colored progress track under the supporting text **only if/when a per-project percent-complete value becomes available** — the app's current `Project` model has no completion percentage (it has status enum + rate, not progress), so there's nothing to drive a progress bar from today. Note this as a visual-reference-only item per the task's own instruction (no data model changes in this pass) rather than fabricating a fake progress value.
- FAB → standard FAB restyle from Phase 2.

### Money (`presentation/screens/money/MoneyScreen.kt` + sheets)
- `SecondaryTabRow`/`Tab` (Invoices/Expenses/Tax) → recolor the selected-tab indicator to `brand`; structure unchanged.
- **Invoices tab** — `InvoiceRow` (`ListItem`) → invoice-row + tag style: wrap in `panel` container, add a `document-icon`-style leading badge (38dp, `Shapes.small`-ish, `surfaceSoft` bg, `brand` icon) in place of no current leading icon, map `InvoiceStatus` to the tag palette: `DRAFT`→ no tag or a neutral `line`-bordered label, `SENT`→ `tagBlueBg`/`tagBlueFg`, `OVERDUE`→ `tagAmberBg`/`tagAmberFg`, `PAID`→ `tagGreenBg`/`tagGreenFg` (replacing the current plain `AssistChip`/`Text` status display). `InvoiceBuilderSheet.kt`'s `ModalBottomSheet` → action-sheet style.
- **Expenses tab** — `ExpenseRow` (`ListItem`) → workspace-row style: the existing 40dp receipt-photo thumbnail (`AsyncImage`, `RoundedCornerShape(6.dp)`) is already a leading-element row, close to the mock's avatar-leading `workspace-row`; just bump its corner radius to match `Shapes.small` (13dp, closer to the mock's badge radius than the current 6dp) and wrap the list in the same `panel` container/divider treatment as the other tabs. Deductible flag text → tag style (`tagGreenBg`/`tagGreenFg`, label "Deductible"). `ExpenseFormSheet.kt`'s `ModalBottomSheet` → action-sheet style; its Camera/Gallery photo-source choice (if presented as two buttons) is the single best fit in this app for the mock's literal 2-column action-grid tappable-card pattern — restyle those two buttons as action-grid cards with icon badges (camera badge in one tint, gallery badge in another).
- **Tax tab** — the two `Card`s (`Deductible expenses`, `Estimated deduction`) → workspace-stat card style ([19 §7.3](19-ui-design-system.md#73-metric-card-2-column-grid) sizing, or more precisely the `workspace-stat` variant: big `displaySmall`/28sp Manrope figure + muted detail line below, full-width rather than paired in a 2-column grid since there are only two and they read better stacked). `FilterChip` period selector → recolor selected state to `mint`/`brand`, same as Home's export-period chips. `TaxProfileDialog` (`AlertDialog`) → shared `AlertDialog` restyle only.

### Clients (`presentation/screens/clients/ClientsScreen.kt`)
`ClientRow` (`ListItem`, currently no leading element shown in the excerpt) → workspace-row/avatar-list style: add a leading avatar badge (42dp, `Shapes.small`-ish 13dp corners, initials, rotate through the four avatar tone pairs from [19 §7.10](19-ui-design-system.md#710-avatars) per client for visual variety — a simple hash-of-id-to-tone, not a data model change), wrap list in `panel` container with dividers, trailing chevron (`Icons.Outlined.ChevronRight`) if the row is purely a navigation/edit affordance (it already is — `onClick` opens the edit form). `ClientFormSheet.kt`'s `ModalBottomSheet` → action-sheet style, same as the other two sheets.

## Risk / ambiguity list

Things inferred or extrapolated rather than directly observed in the Figma export, in order of how much they could legitimately be second-guessed:

1. **Dark color scheme** ([19 §1.4](19-ui-design-system.md#14-dark-scheme--inferred-not-observed)) — the mock has no dark-mode artboards at all; the dark scheme here is a same-hue derivation, not a verified design. Should get a real design pass before shipping, not just an engineering guess.
2. **Google Fonts runtime setup specifics** — the certificate-fingerprint resource array and exact `ui-text-google-fonts` artifact version need to be pinned against whatever Compose BOM version the project is actually on; the mechanism described (downloadable font provider + cert array) is correct and standard, but the exact file/line is not written out here since it depends on the live `libs.versions.toml` at implementation time.
3. **Icon substitution fidelity** — `material-icons-extended`'s Outlined set is a practical stand-in for the mock's custom 1.8px-stroke hand-drawn icons, not a pixel match; a few (briefcase→Work, wallet→AccountBalanceWallet) are closer in spirit than literal shape.
4. **Backdrop blur on the bottom nav bar** — Compose's stock `NavigationBar` has no built-in blur-behind-content effect; genuine blur needs either a custom `RenderEffect`/`Modifier.blur` composition behind the bar (API 31+, with a flat-alpha fallback below that) or a third-party blur library. The plan above defaults to a flat 95%-alpha fill as the practical fallback and flags true blur as a nice-to-have, not a guaranteed deliverable.
5. **Home hero vs. metric-grid treatment** — addressed directly above with a stated argument (apply metric-card style to all three peer metrics rather than forcing one into the single-hero slot), but it is a judgment call the user may want to override after seeing it built.
6. **Work screen's missing progress-bar data** — the mock's project-row progress bar has no corresponding field in the current `Project` model (status/rate only, no completion percent); not implemented rather than faked.
7. **Shadow tuning** — the `Modifier.shadow(ambientColor=, spotColor=)` values in [19 §5](19-ui-design-system.md#5-elevation--shadow) are a direct alpha/RGB translation of the CSS `rgba()` shadows, but Android's shadow renderer and CSS `box-shadow` don't diffuse identically; expect to nudge the `elevation` dp values during implementation to match the mock's visual softness rather than treating the stated numbers as final.
